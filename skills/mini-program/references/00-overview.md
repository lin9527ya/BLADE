# 00 · 方法论全景

## 标准流程

| 阶段 | 动作 | 产出 |
|---|---|---|
| 1 信息收集 | 小程序名称/AppID/主体/服务域名/隐私政策/插件/关联公众号 | 资产表 |
| 2 取包 | PC 缓存 / Android / iOS；主包+分包+插件；记录版本与哈希 | `*.wxapkg` + SHA-256 |
| 3 解密解包 | V1MMWX 解密；还原工程目录；质量门禁 | 源码树 + manifest |
| 4 静态审计 | 路由/接口/密钥/云环境/签名/web-view/插件 | 接口清单、密钥清单 |
| 5 抓包 | PC Proxifier / 模拟器 / iOS / 透明代理 | 真实请求样本 |
| 6 接口测绘 | 走完页面；记录 token/openid；鉴权矩阵 | 路由表、接口×身份矩阵 |
| 7 接口测试 | 未授权/越权/逻辑/注入/上传/支付/云开发 | 候选漏洞列表 |
| 8 最小验证 | 双账号；IDOR ≤5 条；不批量；不真实支付 | PoC + 请求响应 |
| 9 证据 | 脱敏、哈希、时间戳、页面路径、版本 | 证据包 |
| 10 报告复测 | 按模板提交；修复后复测 | 报告 + 复测结论 |

## 与 Web/APP 测试的差异

- 目标定位不是 URL，而是 **AppID + 页面路径 + 云环境/函数/集合**。
- 登录态是 `wx.login → code → code2Session → openid/session_key → 自定义 token`，不是 Cookie。
- 请求可能被签名/加密；报告要说明如何解密/重签。
- 云开发没有传统 URL；要写 envId、函数名、集合名、规则。
- 证据必须含小程序名称/页面路径截图或录屏；记录微信版本/基础库版本。
- 客户端-only 的“成功”不算；必须证明后端状态/数据变化。

## 三类独有攻击面

1. **微信登录与开放数据**：code2Session、session_key、unionid、getPhoneNumber。
2. **云开发（CloudBase）**：云函数、数据库规则、存储规则、HTTP API、环境共享、未登录模式。
3. **微信开放能力**：小程序码/URL Link/Scheme、订阅消息、客服消息、微信支付、发货信息、内容安全、分享/朋友圈、跨小程序跳转。

## 产出物清单

- 资产表：AppID、主体、域名、云环境、插件、关联应用。
- 接口清单：METHOD + URL + 来源文件:行 + 鉴权方式 + 测试状态。
- 密钥清单：类型 + 脱敏值 + 文件:行 + 有效性验证结论。
- 路由表：主包/分包/插件页面 + 高价值标记。
- 鉴权矩阵：接口 × 身份（匿名/A/B/管理员/过期/伪造）。
- 证据包：请求响应、截图、录屏、源码行、包哈希。
- 报告：每条漏洞的复现、影响、修复、证据。
