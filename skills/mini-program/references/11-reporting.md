# 11 · 报告写法

## 结构

1. **基本信息**：小程序名称、AppID、主体、版本、基础库、微信版本、设备/系统、入口路径/小程序码、云环境 ID。
2. **漏洞概述**：类型、CWE/OWASP 映射、等级、影响范围。
3. **复现环境与账号**：账号 A/B、时间、IP、授权依据、测试数据量。
4. **复现步骤**：编号步骤、页面路径、请求/响应原文、A/B 对比、关键参数高亮。
5. **影响与证据**：可读字段、记录数（≤5）、业务影响；截图/录屏；证据哈希。
6. **根因分析**：前端信任、后端缺鉴权、云规则错误、签名/加密缺陷、支付状态机。
7. **修复建议**：后端鉴权、云函数校验、DB/存储规则、服务端算价、密钥轮换、隐私整改。
8. **证据附件**：Burp XML/项目、截图、录屏、请求 ID、时间戳。

## 与 Web 报告的差异

- 目标定位：**AppID + 页面路径 + 云环境/函数/集合**，不是 URL。
- 登录态：`code→openid→token`；写清账号、openid（脱敏）、token 获取方式。
- 请求可能被签名/加密；说明如何解密/重签。
- 云开发无传统 URL；写 envId、函数名、集合名、规则配置。
- 证据必须含小程序名称/页面路径截图或录屏。
- 记录版本/基础库/微信版本。
- 客户端-only “成功”不算；必须证明后端状态/数据变化。

## 定级参考

| 类型 | 常见定级 |
|---|---|
| 未授权访问敏感数据/管理接口 | high/critical |
| 水平越权读取大量用户敏感数据 | high |
| 普通越权（少量、非敏感） | medium |
| 垂直越权到管理后台 | high |
| 支付金额篡改/0 元购 | critical/high |
| 云函数未授权执行管理操作 | high/critical |
| 云数据库/存储开放读全量 | high |
| 硬编码 AppSecret/AKSK（有效） | high/critical |
| 仅源码泄露/可反编译无敏感信息 | low/info（常被驳回） |
| 隐私合规问题 | 按监管口径，通常中高危 |

## 常见驳回原因

- 只改前端/响应包，后端未接受；无实际数据。
- 读取公开信息/商品数据；无敏感性。
- 批量读取/拖库。
- 使用他人真实账号/手机号；证据不可用。
- 无法复现；缺请求/响应/页面路径。
- 与已知/重复漏洞重复。
- 测试了非授权资产/第三方。
- 支付漏洞仅理论推测/沙箱不生效。
- 仅“能反编译/没加固/源码泄露”但无敏感信息。

## 证据要求

- 请求/响应原文（或平台 traffic ID）。
- 页面路径/小程序码截图。
- A/B 账号对照（脱敏）。
- 源码文件:行（解包产物路径）。
- 包 SHA-256、工具版本、质量分。
- 复现命令（curl/Python/平台 http_request 参数）。
- 修复建议可执行（具体到接口/规则/配置）。
