# OPSEC / 隐蔽作战纪律

核心：打得进 ≠ 打得稳。被发现即行动归零。每个动作执行前先问「这步在防守方眼里长什么样」。

## 渐进暴露（先被动，后主动）

- 被动侦察优先：证书透明、被动 DNS、搜索引擎、资产测绘引擎。能公开情报拿到的，不主动碰目标。
- 确认无强监控后再主动扫描；最后才做利用与落地。
- 每升一级先问「值不值得暴露」，并把判断写进 fact，供规划者复用。

## 速率与时序

- 扫描限速：`nuclei -rl`、`nmap -T2 --max-rate`、`ffuf -p` 延迟，避开 WAF/IDS 阈值。
- 高危动作低频，加随机 jitter；按目标作息选时段，避开业务高峰，也避开深夜（贴合正常作息最不显眼）。
- 限速是**授权约定的一部分**：范围里写了速率上限就按上限执行，不靠换 IP、换头绕过自己承诺过的速率。

## 流量混淆

- 请求贴合正常业务：常见 UA/Referer、合法路径、正常参数形态。
- 重武器启用前先探防御面（进程列表、已知 EDR/SIEM agent 特征）。有监控时优先静默手法，确认无监控再上自动化批量。

## 封禁后的处置（授权范围内）

- 被应用层黑名单拦截时，可验证 CDN/回源对转发头的信任：`X-Forwarded-For`、`X-Real-IP`、`CF-Connecting-IP`、`True-Client-IP`。
- 验证方法：正常请求返回黑名单页，加上转发头后返回正常 200，说明应用信任该头；不同 CDN 可能信任第一个或最后一个值。
- 目的是**证明信任缺陷并写进结论**，不是持续规避封禁：确认后按约定速率继续，不轮换伪造 IP 长期绕过限流。

## 最小足迹

- 能内存执行就不落盘（memfd、DDexec、反射加载），减少磁盘残留。
- webshell/上传物：强口令、非常见路径、功能伪装；用途与位置用 `report_artifact` 记入遗留物台账。
- 隧道走 443/DNS 等常见出站；工具用完即删（如 `/dev/shm`），清理动作与证据一并留档。

## 日志与审计边界（硬约束）

- **不修改、不删除、不清空目标的日志与审计记录**，也不修改文件时间戳掩盖痕迹——那是毁证，不是隐蔽。
- 不动监控 / 审计 / EDR 服务：停掉它本身就是最响的告警。
- 自己的跳板机可以处理本地 shell 历史（`unset HISTFILE`、`set +o history`），但那属于本机卫生，不等于可以动目标证据。
- 清理自己留下的落地物，按遗留物台账逐项执行并保留清理证据；清理自己的东西与销毁对方证据是两件事。

## 交付边界

- 隐蔽手法的价值要落到结论上：绕过了什么、证明什么缺陷、影响是什么；只写「我绕过了」不算结论。
- 影响目标可用性的动作（压测、批量写、删库）一律不做，除非授权文件明确允许且已核对范围。
