# Pojun 功能分析与 BLADE 可借鉴清单

> 分析对象：`/home/kali/Pojun` v0.4.68（`e85682a`，2026-11-13）
> 对照对象：BLADE `0.9.12+`（ARTEX parity 分支）
> 性质：只读分析；本文只给结论与落点，不代表已实现。

## 1. 一句话结论

Pojun 与 BLADE 同源，但演进方向不同：

- Pojun 强在**自主推进、证据可信工程、执行面工具、漏洞情报运营、交付产品化**；
- BLADE 强在**黑板/写入权威、战果台账、流量证据、统一报告、出口隔离、审批范围门、全局播报**。

因此不能整体照搬。最适合 BLADE 的是“能力加法”：新工具、新证据门、新交付层；**不要把 Pojun 重新引入的探索约束直接回灌到 ARTEX parity 的 planner/engine**。

## 2. Pojun 功能地图

### 2.1 自主推进与长跑治理

- **Autopilot**：60 秒停滞看门狗；按 `facts + findings + assets` 增量判断进展；有 worker 在跑时窗口放宽 2 倍；连续无进展唤醒 planner；deadline 自动延长。
- **目标续杯**：目标全部达成后，如果还有未测资产或 high/critical 未闭环，自动追加下一层目标。
- **Idle-stop**：worker 连续无写回先提示，之后仍无产出才真正收场；写回类工具豁免。
- **队列治理**：`intent_queue_limit`、本轮新增上限、积压清单、排队意图退役、`requires_intents`。

代码：`server/autopilot.go`、`server/autopilot_extend.go`、`server/auto_finish.go`、`agent/idlestop.go`、`server/engine_guard.go`。

风险：`autopilot_relentless` 默认会抑制 idle/rounds/coverage 收尾和意图预算，成本无界；与 BLADE 已删除 anti-stall、completion gate、队列限制的方向冲突，只能任务级 opt-in。

### 2.2 证据与漏洞质量

- critical/high 最小证据长度：critical 200 字、high 120 字。
- 机械验证信号：HTTP 状态码、curl/sqlmap/nuclei 输出、JSON 字段等。
- 纯版本/banner 匹配不能作为 high/critical 漏洞证据。
- **证据逐字回验**：`report_finding` 的 evidence 必须能在本次真实工具输出中找到；支持 off/warn/block。
- L1-L4 证据分级、多键去重/合并、批量复测、空报告自动巡检。

代码：`agent/finding_recorder.go`、`agent/finding_workflow.go`、`agent/tool_outputs.go`、`server/engine_guard.go`、`db/finding_keys.go`、`server/report_recovery.go`。

### 2.3 SRC 执行面工具

- `http_request`：原生 HTTP，一次返回状态码/头/正文片段/耗时/正文哈希，大响应落盘。
- `session_login`：form/json/basic/bearer/cookie 五形态登录，任务级 cookie jar 与 curl 互通。
- `auth_request`：用资产上已登记凭据组装带认证命令。
- `diff_responses`：过滤时间戳/nonce 等噪声的结构化响应差分。
- `http_probe`：批量探活，一次调用一行 JSON。
- `api_contract`：OpenAPI/Swagger/Postman 契约枚举。
- `js_audit`：sourcemap/源码泄露、前端密钥、接口与路由提取。
- `poc_scaffold`：SQLi/SSTI/LFI/SSRF/IDOR/JWT/upload/cmdi/race PoC 骨架。

代码：`agent/tools_http.go`、`tools_auth.go`、`tools_diff.go`、`tools_probe.go`、`tools_contract.go`、`tools_jsaudit.go`、`poc_scaffold.go`。

### 2.4 漏洞情报运营

- NVD 全量/增量、CISA KEV、GHSA、GitHub PoC、nuclei 模板。
- 近 7 天高危快通道：只收 CVSS≥9 或 KEV，30 分钟一轮。
- 资产指纹 → CVE 反向匹配并挂 hint；CPE 版本区间三态。
- 限速、可中断同步、配置/诊断页、CWE → skill 联动。

代码：`vulnintel/`、`server/vulnintel_*.go`、`agent/tools_vulnintel.go`。

### 2.5 宿主工具与红队面

- 90 项宿主工具目录：apt/GitHub/pip/script/manual 五类安装配方。
- `hostenv` 体检页、一键安装；`hostd` root 特权助手，只接受白名单 tool ID，Unix socket。
- Listener 回连接收器：单会话 64KB、2000 会话上限、启停走 ask 审批。
- C2 出口三形态：direct / SSH 反向隧道 / manual。

代码：`hosttools/`、`hostd/`、`listener/`、`server/c2_relay.go`。

### 2.6 交付与产品化

- GB/T 9704 风格 Word：封面、目录、页眉页脚、字体嵌入、严重度着色、流量证据、复测、修复路线图、目标达成情况。
- 证据附件：截图/文档/数据文件归档、文档转图预览、在线查看、自动归属漏洞。
- MCP 预设、22 个技能、服务化安装、旁路提问、通知、任务归档。

代码：`report/`、`server/artifacts.go`、`server/artifact_preview.go`、`server/mcpdiscover.go`、`install.sh`。

## 4. 推荐借鉴清单

### P0：高价值、低冲突

| 能力 | 价值 | BLADE 落点 |
|---|---|---|
| 证据硬闸升级：长度 + 机械验证 + 纯版本匹配拦截 + 逐字回验 | 降误报、反幻觉 | `agent/tools.go` 的 `report_finding`、`agent/finding_workflow.go`、`evidence/store.go` |
| SRC 领域工具：`auth_request`、`diff_responses`、`http_probe`、`http_request/session_login` | 登录→越权→回读、双响应差分、sourcemap 泄露、PoC 复用 | `agent/tools_insert.go` 的 `WorkerTools`、`agent/exectools.go`、`server/execution.go` |
| 攻击链续跳：high/critical 后由 planner 决定下一跳 | 从“发现”推进到“影响” | `server/attack_chains.go`、`db/chain_ledger.go`、`add_intent` 触发器 |
| 报告目标达成小节 | 交付诚实呈现 | `report/report.go`、`report/docx.go`、`server/report_api.go` |
| MCP 预设 + 技能速查块 | 低成本体验/能力可见性 | `web/src/app/(main)/system/mcp/page.tsx`、`server/assembly.go` |

### P1：可选增强

- Autopilot 受限版：停滞唤醒、deadline 延长、目标续杯；默认关闭，保留 token 预算和人工审批；不搬 `relentless`。
- Idle-stop：默认关闭，观察模式。
- 批量复测；漏洞情报最小闭环（先 KEV + 快通道 + GHSA/OSV）；证据附件预览；Word 公文升级。
- 技能速查、CWE/ATT&CK 标签、压缩器独立 profile。

### P2：重资产、按需

- 90 项宿主工具 + hostd 安装器（先做只读 inventory）。
- Listener/C2（BLADE 已有 OAST；若做只做接收+留证+ask 审批，不做交互式 C2）。
- 全量 NVD/PoC 管线、跨平台服务化安装、22 个技能整库复制。

## 5. 不建议照搬

1. 队列上限、`requires_intents`、`goal_met` 硬闸门、autopilot relentless 默认模式：BLADE 0.9.10 起有意删除这些探索约束。
2. Pojun 的 `criteria`：README 声称目标带验收标准，但公开版 `set_goals` 实际只写 `text/vulnclass`，报告读取的 `criteria` 永远为空，不能按文档实现。
3. 证据“明文保真”：与 BLADE 的 secret masking/合规取向冲突，建议按任务策略开关，默认脱敏。
4. root hostd 与 C2 SSH 中继：hostd 的 GitHub 下载无校验和；C2 使用 accept-new 主机密钥和 sshpass/DB 密码，合规风险高。
5. 自动合并所有弱键：BLADE 当前“相似即拒收 + 人工 merge”更保守；先做强键合并候选。
6. 整文件复制提示词/技能：Pojun 公开版存在 prompt 引用不存在工具（如 `kb_search`、`session_request`）和 `criteria` 只读不写等漂移，移植前必须对照工具注册表和 schema。

## 6. 建议落地顺序

1. **第一批**：证据硬闸 → SRC 领域工具（auth_request、diff_responses、http_request/session_login、http_probe）→ 报告目标达成小节。
2. **第二批**：攻击链续跳（trigger 方式）→ MCP 预设/技能速查 → 压缩器独立 profile → 空报告巡检。
3. **第三批**：Autopilot 受限版、批量复测、Vulnintel 最小闭环。
4. **第四批**：hostd/工具目录、listener/C2、完整 NVD、跨平台服务化安装。

## 10. 第二批实施记录（2026-11-13）

本批按 §6 的第二批顺序落地，全部保持 ARTEX 黑板/意图流程不变：没有新增探索约束、
队列上限、完成门或强制续跳。除空报告巡检外均默认开/无额外成本，空报告巡检默认关。

### 10.1 攻击链续跳（trigger 方式）

- 新增 `server/attack_chain_continuation.go`：独立的 finding 水位
  （`schedKeyLastAttackChainFinding`），不依赖自定义 agent 触发器是否配置。
- 新的 high/critical finding 会向该任务 planner 投一条**非强制 hint**：
  评估能否推进到影响面，由 planner 自行决定是否 `add_intent`；
  提示明确写明「已有意图覆盖/仅版本线索时不要重复探测」「不构成必须派单」。
- 同一 tick 内按任务聚合，单条提示最多列 8 条 finding；时间线同时落一条 system 活动。
- 设置 `attack_chain_continuation`（默认开），可在「系统配置 → 安全与策略」关闭。
- **不创建意图、不改完成门、不限制队列**；与 BLADE 已删除的 anti-stall/队列约束不同。

### 10.2 MCP 预设 / 技能速查

- MCP 推荐目录在 P28 已存在（`web/src/lib/mcp-catalog.ts` + MCP 页「推荐目录」弹窗，
  只预填、不自动安装），本批复核后保留。
- 新增 `DeferredInfo.CapabilityIndex`：在 system 稳定前缀中渲染一张紧凑的
  **能力速查**，列出本 agent 可见的技能（名称 + 一句话描述）与 MCP 服务器（名称 + 工具数）。
- 顺序固定为「常驻技能正文 → 能力速查 → deferred 工具块」，仍全部属于缓存稳定的
  system 段；完整步骤仍由 `Skill(name)` 读取，速查块不复制技能正文。
- 由 `server/assembly.go` 的 `renderCapabilityIndex` 生成，名称排序保证缓存前缀稳定。

### 10.3 压缩器独立 profile

- 新增设置 `compactor_llm_profile_id`（0 = 跟随任务链/角色绑定），在「系统配置 →
  执行与并发 → 压缩摘要模型」选择。
- 覆盖两条压缩路径：
  - 冷节点摘要 `agent.Compactor`：配置独立 profile 时改用该 provider；
  - 上下文压缩 `InstallContextManager` / `DomainCompactor`：通过
    `agent.CompactionLLM` 覆盖摘要调用，工具循环仍用任务模型。
- 独立 profile 的 quota/失败**不会推进任务的 LLM 故障转移链**（`profileID=0`），
  避免摘要模型耗尽把任务主模型标成 exhausted。
- 摘要窗口、输出上限、流式/非流式随该 profile 的配置；设置变更会重建任务 agent bundle。

### 10.4 空报告巡检

- `findings` 增加 `report_patrol_at` / `report_patrol_attempts`，并加部分索引。
- 新增 `db.ClaimFindingReportPatrol`：`FOR UPDATE SKIP LOCKED` 原子领取，
  只挑已确认（或 high confidence / 复测 reproduced|fixed）、有 task+node、创建满 10 分钟
  且仍无详细报告的 finding；每条最多 2 次、间隔至少 30 分钟。
- 调度器每 10 分钟巡检一次（设置 `empty_report_patrol`，**默认关**）；命中后复用现有
  `reporter` agent 补写 `update_finding_report`，不新建报告通道。
- reporter 不存在/停用时不派单；证据不足时按 reporter 既有纪律只说明缺口，不臆造。
- 默认关的原因：每条 finding 会触发一次完整 LLM 会话，成本与 finding 数线性相关。
