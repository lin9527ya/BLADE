# 功能拓展路线图

> 状态：第 1、2、3 项已完成；其余待做
> 更新：2026-11-11
> 边界：黑板架构与探索意图流程已冻结，不再优化；本轮只做**本地闭环**，不引入新的外部 API 依赖。
> 权威实现以代码与 `CHANGELOG.md` 为准，本文只记录方向、取舍与验收口径。

## 背景

BLADE 的探索/执行/交付能力已经较完整：战果、痕迹、遗留物、CVE、打法库、AD/云导入、长任务、
OAST、统一报告、复测、归档、通知、保留清理、MCP/Skill/自定义工具都已落地。当前主要缺口不在探索
算法，而在产品化闭环：

- 交付正确性与导出闭环（报告不可下载、SRC 批量 500 条静默截断、ZIP 全内存、无整包校验）。
- 任务文件/归档完整度（无任务级文件浏览；归档缺复测/案例/工具执行数据）。
- 资产与 CVE/打法库的导入导出闭环、资产来源与生命周期。
- 计划任务运营面、事件通知覆盖面。
- 可观测性、成本核算与前端轮询收敛。

### 1. 交付包与报告分发闭环

**问题**

- `GET /api/report` 只返回内联 Markdown，无 `Content-Disposition`，前端只能复制；完整报告无 DOCX。
- `buildSrcBatch` 用 `ListFindingsPage(..., 1, 500)` 且丢弃 total，超过 500 条发现静默少交。
- `buildSrcZip` 全内存 `bytes.Buffer`，大任务有 OOM 风险；交付 ZIP 无整包 manifest/SHA256。

**改动**

- `server/report_api.go`：抽出 `buildFullReport`；`GET /api/report` 增加 `format=md|docx`，默认行为不变。
- `report/docx.go`：新增 `FullDOCX(markdown)`，复用现有 OOXML package 与样式。
- `server/src_batch.go`：ID 快照 + 分块全量读取；写临时文件 + `http.ServeContent`。
- 新增 `server/zip_manifest.go`：`manifest.json` + `SHA256SUMS`。
- 前端 `api.ts` / `report-tab.tsx`：下载 Markdown / DOCX。

**验证**

- >500 条发现不截断；manifest 哈希可逐条校验；DOCX 可打开。
- 现有报告确认门/分区/去重测试与 `routes.golden` 不变。

### 2. 计划任务运维台

**问题**：只有基础 CRUD 与建任务弹窗，无独立页面、暂停/恢复、立即运行反馈、运行历史。

**改动**

- `db/schedules.go`：读取 `schedule_runs`（已有表与索引）。
- `server/schedules.go` + `routes_tasks.go`：`GET /api/task-schedules/{id}/runs`；DTO 补 next/error/last_task。
- 前端新增计划任务页面（列表、暂停/恢复、立即运行、历史、跳转任务）。

**验证**：暂停不触发、恢复按 `next_run_at` 继续；立即运行不推进排期；历史分页/状态正确。

### 3. 全局战果与凭据台账

**问题**：据点/凭据/遗留物/痕迹/`credential_attempts` 只有任务内视图，无跨任务总账。

**改动**

- 新增 `db/loot_ledger.go`：跨任务分页查询，按 kind/state/company/campaign/task/time 过滤；凭据不返回明文。
- `db/credential_attempts.go`：全局分页/过滤与索引。
- 新增 `/api/loot`、`/api/loot/export`、`/api/credential-attempts`；前端新增「战果」页面。
- 报告与页面复用同一口径；明文仍走现有 reveal 接口并留痕。

**验证**：组合过滤、导出不含 secret、大数据量索引与分页。

### 4. 运维可观测性、成本与轮询收敛

**问题**：审计仅进程内 ring；`/api/metrics` 为自定义 JSON 且需登录，无 readiness；LLM 无货币成本；
前端约 38 处轮询。

**改动（分片）**

- 4a：`/api/metrics.prometheus`（手写 text exposition）+ `/api/readyz`。
- 4b：guard 审计持久化到 `security_audit`，ring 保留实时视图。
- 4c：`llm_prices` + `llm_usage` 成本计算；先只读看板，再公司级预算。
- 4d：任务状态/审批/聊天优先 SSE；`GET /api/tasks/{id}` 加 ETag；合并仪表盘请求。

**验证**：Prometheus 可抓取、readyz 故障注入、重启后审计可查、成本单测、请求数下降。

### 5. 资产与情报数据闭环

**问题**：资产只有 `last_seen`，无 first_seen/status/provider/同步批次；资产导出前端封顶；
CVE 只有导入无导出；打法库无导入/导出。

**改动**

- `assets` 增 `first_seen/status/provider/last_sync_batch_id`；新增 `asset_sources`/`asset_sync_batches`。
- 统一资产来源记录；服务端流式导出 CSV/JSON；导入导出 schema 对齐。
- CVE/打法库增加 export；资产页增加生命周期/来源筛选。

**验证**：schema 幂等、导出→导入 round-trip、来源计数一致。

### 6. 交付物台账与项目级汇总报告

**问题**：无交付物实体/版本/签收；单任务报告之外没有战役/公司级客户可读汇总；归档无下载端点。

**改动**

- 新增 `deliverables`/`deliverable_versions`/`deliverable_acceptances`。
- 支持按 task/campaign/company 生成 MD/DOCX/ZIP、版本对比、签收与审计。
- `report/aggregate.go` 组装项目级汇总；归档增加下载端点（不开放任意上传导入）。

**验证**：汇总口径与单任务报告一致、版本哈希不可变、签收审计、归档下载哈希一致。

## 推荐顺序

1. 交付包与报告分发闭环（先修客户可见的正确性 bug）
2. 计划任务运维台（最小成本补齐自动化运维面）
3. 全局战果与凭据台账（数据已在库，只缺读取/导出）
4. 运维可观测性/成本中的 4a+4c 小片
5. 资产与情报数据闭环（涉及迁移与多导入路径）
6. 交付物台账与项目级汇总（依赖 1 与 4 的数据口径）
7. 4b/4d（审计持久化、轮询→SSE）按运维痛点穿插

## 第一项实施要点

- 报告：`GET /api/report?format=md|docx`，默认仍为内联 Markdown；文件名安全清洗。
- DOCX：纯 Go OOXML，不引 Chromium/LibreOffice；覆盖标题、列表、代码块、分隔线。
- SRC 批量：按任务 finding ID 快照分块读取，禁止 500 条静默截断；ZIP 写临时文件后
  `http.ServeContent` 返回。
- 包内新增 `manifest.json` 与 `SHA256SUMS`；跳过项写 `skip_reason`。
- 前端报告 Tab 增加「下载 Markdown」「下载 DOCX」。

**验收命令**

```bash
go test -race -count=1 ./report ./server -run 'Test(FullDOCX|Report|SrcBatch|RouteSnapshot)'
BLADE_TEST_PG_DSN=... go test -race -count=1 -p 1 ./...
go vet ./... && gofmt -l .
cd web && npx tsc --noEmit && npm test && npm run build:static
```

LLM 响应缓存。可选后续：Repeater 工作台、历史漏洞批量 review runs、Basic Auth 前置网关、
按 LLM Profile 的 worker pools。
