# IM 控制使用说明（钉钉 / 飞书）

包含 IM 控制功能的 BLADE 构建支持通过钉钉、飞书机器人在手机上控制任务：查看任务、创建任务、暂停/继续、编辑任务元数据与资产范围。消息通过平台**长连接**接收，BLADE 仍只监听本机 `127.0.0.1:9898`，不需要公网 IP 或反向代理。

> 支持两种交互：以 `/` 开头的确定性命令，以及直接发自然语言交给内置 `auto` 会话 Agent 处理。所有操作都受“允许用户”白名单和 viewer/operator 角色约束。

---

## 一、准备工作

1. 确认 BLADE 已升级到包含 IM 控制的版本，并能正常访问「系统设置 → IM 控制」。
2. 在钉钉或飞书开放平台创建**企业内部应用 / 自建应用**，启用机器人能力。
3. 记录应用的 App ID / Client ID 与 App Secret / Client Secret。凭据只保存在 BLADE 的数据库中，管理接口只回显掩码。
4. BLADE 进程需要能访问对应平台的公网地址（长连接由 BLADE 主动外连）。

---

## 二、钉钉接入

### 1. 创建应用与机器人

1. 登录[钉钉开放平台](https://open.dingtalk.com/)，进入「应用开发 → 企业内部应用」，创建应用。
2. 在应用能力中启用「机器人」。
3. 机器人消息接收方式选择 **Stream 模式**（不是 HTTP 回调）。
4. 按平台提示开通机器人消息接收与发送所需权限，保存并发布应用版本。
5. 在「应用信息」中复制 **Client ID（AppKey）** 与 **Client Secret（AppSecret）**。

### 2. 在 BLADE 添加连接

进入「系统设置 → IM 控制 → 连接 → 新增连接」：

| 字段 | 填写 |
| --- | --- |
| 名称 | 便于识别的名称，例如「钉钉运维」 |
| 平台 | 钉钉 |
| App ID / Client ID | 钉钉应用的 Client ID（AppKey） |
| App Secret / Client Secret | 钉钉应用的 Client Secret（AppSecret） |
| 启用长连接 | 打开 |
| 允许群聊控制 | 默认关闭；需要群聊时再打开 |

保存后状态会从 `connecting` 变为 `connected`；保存配置会自动重连，不需要重启 BLADE。若状态为 `error`，先看卡片上的 `last_error`。

### 3. 把机器人加入会话

- 私聊：在钉钉中搜索机器人名称，直接发起单聊。
- 群聊：把机器人加入群，并在群里 **@机器人** 后发命令；同时需要在 BLADE 连接中打开「允许群聊控制」，并把发送者加入允许用户。

---

## 三、飞书接入

### 1. 创建应用与机器人

1. 登录[飞书开放平台](https://open.feishu.cn/)，创建「企业自建应用」。
2. 在「添加应用能力」中启用「机器人」。
3. 进入「事件与回调 → 事件订阅」，订阅方式选择 **使用长连接接收事件**，并添加事件：
   - `im.message.receive_v1`（接收消息 v2.0）
4. 在「权限管理」中开通机器人收发消息所需权限，常见为：
   - `im:message`（获取与发送单聊、群组消息）
   - `im:message:send_as_bot`（以应用身份发消息）
5. 创建并发布应用版本，必要时由企业管理员审核通过。
6. 在「凭证与基础信息」中复制 **App ID** 与 **App Secret**。

如果飞书事件订阅启用了 **Verification Token** 或 **Encrypt Key**，在 BLADE 连接中一并填写；未启用就留空。

### 2. 在 BLADE 添加连接

进入「系统设置 → IM 控制 → 连接 → 新增连接」：

| 字段 | 填写 |
| --- | --- |
| 名称 | 便于识别的名称，例如「飞书安全群」 |
| 平台 | 飞书 |
| App ID | 飞书应用的 App ID |
| App Secret | 飞书应用的 App Secret |
| Verification Token（可选） | 事件订阅启用验证令牌时填写 |
| Encrypt Key（可选） | 事件订阅启用加密时填写 |
| 启用长连接 | 打开 |
| 允许群聊控制 | 默认关闭；需要群聊时再打开 |

飞书密钥字段同样是掩码回显：编辑时留空表示保留原值。

### 3. 把机器人加入会话

- 私聊：在飞书中搜索机器人名称发起单聊。
- 群聊：把机器人添加进群，并在群里 **@机器人** 后发命令；同时打开连接的「允许群聊控制」，并把发送者加入允许用户。

---

## 四、登记允许用户

IM 控制默认拒绝所有用户。未登记用户发消息时：

- 不会执行任何任务操作；
- 消息日志会留下 `ignored` 记录与审计；
- 机器人回复“未授权”，提示联系管理员。

### 获取用户 ID

1. 让对方先给机器人发一条消息（私聊或群里 @）。
2. 打开「系统设置 → IM 控制 → 消息日志」，找到这条消息的 `sender_id`：
   - 钉钉：通常是 `staffId`；外部联系人可能回退为 `senderId`；
   - 飞书：通常是用户的 `open_id`。
3. 进入「允许用户 → 添加用户」，填写平台、用户 ID、显示名和角色。

### 角色

| 角色 | 权限 |
| --- | --- |
| `viewer` | 查看任务列表、任务详情、资产范围；不能修改 |
| `operator` | 在 viewer 基础上，可创建任务、暂停/继续、编辑元数据、增删资产范围 |

建议日常手机控制使用单独的 `operator` 账号，不要给所有人开 operator。

## 五、命令

命令必须以 `/` 开头。私聊直接发送；群聊需要 @机器人。命令不区分大小写，参数支持双引号包裹空格。

### 查看

| 命令 | 说明 |
| --- | --- |
| `/help` | 查看当前角色可用命令 |
| `/tasks` | 最近任务列表（默认 15 条） |
| `/tasks running 10` | 只看运行中的任务，最多 10 条 |
| `/tasks paused` | 只看暂停任务；也支持 `all` / `done` |
| `/show 42` | 查看任务 #42 的状态、描述、目标、备注、范围策略等 |
| `/scope 42 list` | 查看任务 #42 的显式资产范围行 |

### 创建

```text
/new 对 example.com 做外部暴露面测试 --name 示例任务 --policy target --scope root_domain:example.com --timeout 7200
```

- `--name`：任务名称，可省略；
- `--policy`：`exact` 或 `target`，`target` 表示目标所属全资产自动可测；
- `--scope`：可重复，格式 `kind:value`；kind 支持 `company`、`root_domain`、`subdomain`、`ip`、`cidr`、`icp`；
- `--timeout`：任务超时秒数，省略或 0 表示不限时。

创建时会先保存任务与范围，再启动探索，避免首轮规划看不到范围。

### 暂停 / 继续

```text
/pause 42
/resume 42
```

终态任务的继续需要仍有未执行意图或未达成目标，否则会明确拒绝。

### 编辑元数据

```text
/edit 42 --name "新名称" --remark "手机修改" --policy target --budget 20
```

- `--name`、`--remark`：名称与备注；
- `--policy`：资产范围策略；
- `--budget`：每 30 分钟凭据尝试预算；`-1` 继承全局，`0` 不限。

任务的描述与目标创建后不可修改；需要改方向请新建任务或使用 Web 端的目标/意图操作。

### 修改资产范围

```text
/scope 42 add root_domain example.com
/scope 42 add ip 203.0.113.10
/scope 42 del 17
```

`add` 的 kind 与创建命令相同；`del` 使用 `/scope 42 list` 返回的范围行 ID。

## 六、自然语言

不以 `/` 开头的消息交给内置 `auto` 会话 Agent。例如：

- “列出正在运行的任务”
- “看看任务 42 现在什么状态”
- “新建一个对 example.com 的测试任务，名字叫手机创建”
- “把任务 42 暂停”
- “把任务 42 的备注改成手机修改”

自然语言回复会尽量简短；需要精确、可重复的操作时优先用命令。IM 运行使用独立的工具白名单：只能访问任务相关工具，不能执行 Shell、读写文件、访问 MCP、修改系统设置、查看凭据或做审批决定。

---

## 七、安全与限制

- **默认拒绝**：只有 `允许用户` 中启用且角色正确的发送者才能操作。
- **群聊默认关闭**：连接上的「允许群聊控制」打开后，仍需发送者在允许用户中；群里只处理 @机器人 的消息。
- **角色隔离**：viewer 只能读；operator 才能创建/暂停/继续/编辑/改范围。
- **不开放的操作**：删除任务、审批决定、系统设置、凭据/密钥查看、loot_exec 开启、拦截规则、planner 提示词、LLM 配置、任务描述/目标修改。
- **工具面收紧**：IM Agent 的执行工具在装配阶段被替换为任务工具白名单，平台消息中的提示注入无法拿到 Bash/文件/MCP 等工具。
- **幂等**：平台重试的同一条消息按 `(连接, 平台消息 ID)` 只处理一次；重复投递不会重复建任务。
- **限流**：每用户 10 条/分钟，每连接 60 条/分钟；自然语言并发最多 4 条。
- **审计**：每条消息和动作落 `im_messages` / `im_actions`，并写 `audit_events`，actor 形如 `im:dingtalk:<user_id>` 或 `im:feishu:<open_id>`。
- **凭据**：App Secret、Verification Token、Encrypt Key 只保存在本机数据库；管理接口只回显掩码，日志不打印明文。
- **回复长度**：超长回复会截断到约 3500 字符；完整内容以 Web 端任务详情为准。

## 八、排障

| 现象 | 排查 |
| --- | --- |
| 状态 `disabled` | 连接未启用；打开「启用长连接」并保存 |
| 状态 `error` | 看卡片 `last_error`；核对 App ID/Secret、应用是否发布、机器人能力是否开通 |
| 一直 `connecting` | 检查 BLADE 出网、平台事件订阅是否为 Stream/长连接模式；飞书是否订阅 `im.message.receive_v1` |
| 私聊无回复 | 消息日志是否有记录；发送者是否在允许用户且启用；角色是否足够 |
| 群聊无回复 | 是否 @机器人；连接是否打开「允许群聊控制」；发送者是否在白名单 |
| 提示未授权 | 把消息日志中的 `sender_id` 加进允许用户（注意钉钉 staffId 与飞书 open_id 的区别） |
| 飞书事件解密失败 | 在连接中填写与开放平台一致的 Encrypt Key / Verification Token |
| 重复消息 | 平台重试会被幂等键忽略；检查消息日志是否只有一条 |
| 修改后未生效 | 保存连接会自动重连；状态仍异常时查看 `blade.log` 中 `[im]` 日志 |

消息日志的状态含义：

- `received`：已接收，等待处理；
- `processing`：处理中；
- `replied`：已生成并发送回复；
- `failed`：执行或回复失败，`error` 字段有原因；
- `ignored`：未授权、群聊未开启或触发限流，未执行操作。

## 九、数据与清理

IM 控制使用以下表：

- `im_connections`：连接配置；
- `im_allowed_users`：允许用户与角色；
- `im_messages`：入站消息、状态与回复；
- `im_conversations`：IM 会话与 BLADE 会话的映射；
- `im_actions`：结构化操作审计（同时写 `audit_events`）。

删除连接会级联删除该连接的消息、动作与会话映射；对应的 BLADE 对话记录不会自动删除。
